# luanma · 乱码克星

**中国語・日本語・韓国語の文字化けを自動で修復します。** 文字化けしたテキストを貼り付けると元の文字に戻し、どの段階でどのエンコーディングを取り違えたのかも説明します。

[English](README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md)

```
$ luanma "縺薙ｓ縺ｫ縺｡縺ｯ"
こんにちは
$ luanma explain --lang ja "╬─╝■├√.txt"
文件名.txt
  誤り1：GBK のデータが CP437(DOS) として読み込まれた
  信頼度 約98%（スコア -0.70 → 2.50）
```

**ブラウザで試す → https://3566264817a-cyber.github.io/luanma/**（HTML ファイル 1 つだけ。オフラインでも動作し、何も送信されません）

## なぜ作ったか

文字化け修復の定番 [ftfy](https://github.com/rspeer/python-ftfy) は、GBK / GB18030・Big5・Shift-JIS・EUC-KR といった CJK のレガシーエンコーディングを[扱わないと明記しています](https://ftfy.readthedocs.io/en/latest/avoid.html)。しかし CJK の文字化けの多くはまさにこれが原因です。UTF-8 の CSV を Excel で開いた、Windows で作った zip を Mac で展開した、Shift-JIS のゲームを中国語版 Windows で動かした……。

luanma はその穴を埋めます。純粋な Python・依存ゼロで、ブラウザ版もあります。

| `浣犲ソ涓栫晫` | 你好世界 | UTF-8 の中国語を GBK として開いた（メモ帳 / Excel） |
| `ÄãºÃ£¬ÊÀ½ç` | 你好，世界 | GBK を MySQL の `latin1` 列に保存 |

正常なテキストは変更しません。正しい文字と文字化けが混在している場合は、部分ごとに修復します。

## インストールと使い方

```bash
pip install luanma          # Python 3.9 以上、依存なし
```

```python
import luanma

luanma.fix_text("縺薙ｓ縺ｫ縺｡縺ｯ")      # 'こんにちは'

r = luanma.fix("æ–‡å­—åŒ–ã‘")
print(r.fixed)                            # 文字化け
print(r.explain("ja"))                   # 取り違えたエンコーディング、補完したバイト数、信頼度
```

コマンドライン：

```bash
luanma "縺薙ｓ縺ｫ縺｡縺ｯ"                # 文字列を修復
luanma explain --lang ja "…"           # 何が起きたかを説明
luanma -f broken.csv -o fixed.csv      # ファイルを修復（生の Shift-JIS / GBK / Big5 / EUC-KR も自動判別）
luanma zip archive.zip                 # zip 内の文字化けしたファイル名の正しい名前を表示
```

## 仕組み

1. **探索**：文字化けは「エンコーディング A のバイト列を B として解釈した」という誤りの連鎖です。UTF-8・GBK・Big5・Shift-JIS・EUC-KR・Windows-1252・Latin-1・CP437 の間で最大 3 段のビームサーチを行い、1 段ずつ逆にたどります。
2. **採点**：候補ごとに「自然な文章らしさ」を採点します。文字頻度（jieba 辞書）、3.1 万の頻出 2 文字語、各国の標準常用字表（GB2312 第一級、Big5 常用字、JIS X 0208 第一水準、KS X 1001 ハングル）を使い、典型的な文字化けの兆候（`�`、私用領域の文字、半角カナ、罫線記号、単語内での文字種の混在、単語にならない漢字の羅列）に減点します。
3. **欠落バイトの補完**：すでに壊れたバイトがある場合は、前後の文脈と文字頻度から推測して補い、いくつ補ったかを報告します。
4. **害を与えない**：文字化けの兆候があるテキストだけを対象にし、明らかに良くなる場合にだけ修正を採用します。

誤修正テスト：正常なテキスト 618 件中、変更されたのは **0** 件。（全実行は 2 コアで約 6 分）Web 版（JavaScript、Chromium で検証）の出力は 99.4% のサンプルで Python 版と一致します。

- バイトが失われないパターンはほぼ完全に復元できます。
- 誤ったデコードでバイト自体が壊れた場合（UTF-8 を Big5 / EUC-KR / Shift-JIS として読んだ等）は情報の一部が失われており、推測できない部分は `�` で示します。これらの数値は正直な上限であり、バグではありません。特に「UTF-8 を Big5 として読む」は欠損が大きすぎるため、推測せずそのまま残します。

## 制限

- 1〜2 文字だけの極端に短いテキストは曖昧なため、基本的に変更しません。
- 対応するのは上記のエンコーディングのみです。欧米語の UTF-8 ↔ Windows-1252 の問題には ftfy を使ってください。
- 文字頻度データは中国語由来です。日本語・韓国語は主に JIS / KS の標準字表に頼っており、十分実用的ですがやや粗めです。

## メンテナンス不要

エンコーディングは固定された国家規格で、頻度表は `tools/build_tables.py` で一度生成してコミットするだけ。ネットワーク不要、モデルのダウンロード不要、実行時の依存もありません。

## ブラウザ版

`docs/index.html` は単体で動く 1 ファイル（約 270 KB）で、`python tools/build_web.py YOUR_NAME/luanma` で生成します。公開方法：リポジトリの Settings → Pages → Deploy from a branch → `main` ブランチの `/docs`。ファイルをダウンロードしてローカルで開くだけでも使えます。URL に `?q=...` を付けると入力欄に事前入力されます。
